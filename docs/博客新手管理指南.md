# Firefly 博客新手管理指南

这份指南按你现在的项目设置编写。最重要的一点：**真正的博客项目是 `D:\code-MS\blog\Firefly`**。以后请在 VS Code 打开这个文件夹，并在它里面的终端执行命令。外层 `D:\code-MS\blog` 是包含内层项目的目录，不要在外层提交博客改动。

## 1. 本地打开博客预览

### 用 VS Code 打开正确的项目

1. 打开 VS Code。
2. 点左上角 **文件 → 打开文件夹**。
3. 在路径框输入 `D:\code-MS\blog\Firefly`，选择该文件夹并打开。
4. 看左侧文件树最上方是否能看到 `package.json`、`src`、`public`、`.github`。看到这些就说明打开的是内层博客项目。

也可以在 VS Code 菜单中点 **终端 → 新建终端**。终端提示符路径应以 `D:\code-MS\blog\Firefly` 结尾。若不是，先输入：

```powershell
cd D:\code-MS\blog\Firefly
```

首次使用时安装依赖（电脑需要安装 Node.js 22 和 pnpm；已经安装过时无需每次重复）：

```powershell
pnpm install
```

启动本地预览：

```powershell
pnpm dev
```

终端会显示一个本地网址，通常是 `http://localhost:4321/`。按住 Ctrl 再点击网址，或复制到浏览器打开。改完文件后保存，浏览器通常会自动刷新。按 `Ctrl+C` 可以停止预览。

## 2. 修改常见内容

配置主要放在 `src/config/`。用 VS Code 打开对应文件，修改引号里的文字或 `true` / `false`，保存即可。

| 想修改什么 | 文件 |
|---|---|
| 网站标题、域名、页面开关 | `src/config/siteConfig.ts` |
| 头像、名字、个人签名 | `src/config/profileConfig.ts` |
| 首页大标题、首页诗句、壁纸 | `src/config/backgroundWallpaper.ts` |
| 公告文字和“了解更多”按钮 | `src/config/announcementConfig.ts` |
| 音乐和封面 | `src/config/musicConfig.ts` |
| 左右侧栏模块 | `src/config/sidebarConfig.ts` |
| 顶部菜单 | `src/config/navBarConfig.ts` |
| 个人介绍页面 | `src/content/spec/about.md` |
| 文章 | `src/content/posts/` |
| 动态 | `src/content/dynamic/` |

例如，`siteConfig.ts` 里的 `dynamic: false` 表示动态页面关闭；改为 `true` 才会开放动态页面和菜单入口。侧栏模块在 `sidebarConfig.ts` 中也有自己的 `enable` 开关。

### 在 VS Code 里快速找到文件和文字

- 左侧文件树可逐层展开 `src` → `config` → 目标文件。
- 按 `Ctrl+P`，输入文件名（如 `siteConfig.ts`），按回车可直接打开。
- 在文件里按 `Ctrl+F` 搜索要改的文字；按 `Ctrl+S` 保存。
- 只改引号里的值或明确标出的 `true` / `false`。不要删除逗号、括号或整段配置。

### 具体每个常改文件怎么改

1. **网站标题、域名和开关：**打开 `src/config/siteConfig.ts`。找到 `title` 改浏览器/网站标题；`subtitle` 是副标题；`site_url` 填完整网址并保留 `https://`。下方 `pages` 中每个页面项目可用 `true` 开启、`false` 关闭。例如 `dynamic: false` 关闭动态页。
2. **名字和头像：**打开 `src/config/profileConfig.ts`。`name` 改显示姓名，`bio` 改头像下的个人签名，`avatar` 是头像文件路径；`links` 列表维护 GitHub、邮箱等个人链接。不要保留不属于自己的链接。
3. **首页横幅和背景：**打开 `src/config/backgroundWallpaper.ts`。搜索 `homeText`，`title` 是大标题，`subtitle` 列表是副标题。若只要固定显示一条，将列表改成 `subtitle: ["你的文字"],` 并把 `typewriter.enable` 设为 `false`。壁纸路径也在此文件的 `src` 配置附近，图片本身通常放在 `src/assets/images/`。
4. **公告卡片：**打开 `src/config/announcementConfig.ts`。`content` 写公告；`link.text` 是按钮文字；`link.enable` 决定是否可点击；`link.url` 是点击后地址。是否显示公告卡片还要看 `src/config/sidebarConfig.ts` 中公告组件的 `enable`。
5. **左右侧栏和手机端模块：**打开 `src/config/sidebarConfig.ts`。分别查看 `leftComponents`、`rightComponents`、`mobileBottomComponents` 三个列表。找到想控制的模块（例如 `type: "dynamic"` 或 `type: "announcement"`），改它下面对应的 `enable: true/false`。要在电脑和手机端都隐藏，检查所有列表里同类型模块。
6. **顶部菜单：**打开 `src/config/navBarConfig.ts`。菜单链接由 `LinkPresets` 和导航链接数组生成。若页面由 `siteConfig.ts` 的 `pages` 关闭，相关菜单通常也会自动隐藏；自定义外链则在这里修改名称和 URL。
7. **音乐：**打开 `src/config/musicConfig.ts`。本地歌曲在 `local.playlist` 列表里，每首歌有 `name`、`artist`、`url`、`cover`。音频放 `public/assets/music/`，封面放 `public/assets/music/cover/`；路径从 `/assets/...` 开始。
8. **关于我页面：**打开 `src/content/spec/about.md`，这是 Markdown 文件，直接编辑正文即可。
9. **文章和动态：**文章在 `src/content/posts/`，动态在 `src/content/dynamic/`。每个 `.md` 或 `.mdx` 文件前面的 `---` 区域是文章资料，后面才是正文。

## 3. 管理动态

动态文件放在 `src/content/dynamic/`，每个 `.md` 文件是一条动态。当前动态页面已关闭（`siteConfig.ts` 中 `dynamic: false`），侧栏动态组件也已关闭。

- **暂时隐藏动态：**保持 `dynamic: false`，并保持 `sidebarConfig.ts` 里动态组件 `enable: false`。文件会留在仓库中，但网站不显示。
- **重新开放动态：**把页面开关改为 `dynamic: true`；如果还想在侧栏看到最新动态，再把侧栏对应的动态组件 `enable` 改为 `true`。
- **删除动态：**在 `src/content/dynamic/` 删除对应的 `.md` 文件。删除后会从下一次构建的网站中移除；Git 仍可查看此前版本。
- **新增动态：**在项目终端运行 `pnpm new-dynamic "今天完成了博客更新"`。它会创建一条带日期的动态文件。动态页面关闭时，新动态也不会显示。

建议先隐藏，不要急着删除；确认不需要旧内容后再删除文件。

## 4. 新增文章

### 方法一：用脚手架新建（推荐）

在 VS Code 终端确认路径是 `D:\code-MS\blog\Firefly`，再运行：

```powershell
pnpm new-post "我的新文章"
```

脚本会在 `src/content/posts/` 创建 Markdown 文件。输出会显示新文件路径。按 `Ctrl+P` 输入这个文件名即可打开编辑。

检查文件顶部的文章资料，示例：

```yaml
---
title: 我的新文章
published: 2026-11-24
description: 用一两句话介绍文章内容。
image: ''
tags: [生活, 随笔]
category: 日常
draft: false
lang: zh_CN
slug: wo-de-xin-wen-zhang
---
```

- `title`：文章标题。
- `published`：发布日期，格式写成 `年-月-日`。
- `description`：文章摘要。
- `image`：封面图片；没有封面可留空。
- `tags`：标签列表，方括号里的每个词用逗号隔开。
- `category`：分类名称。
- `draft`：`false` 表示发布，`true` 表示草稿。
- `slug`：网址最后一段，建议使用英文或拼音和短横线；确保每篇文章不重复。

注意：新文章开头必须有一组 `---`，字段格式要保持一致。日期和 `draft` 不能漏。

### 写文章正文

在第二组 `---` 下面开始写正文。例子：

```md
# 这是一段大标题

这是一个段落。段落之间空一行。

## 这是小标题

- 第一条
- 第二条

**这段文字加粗**，`这段是代码`。
```

图片建议复制到 `src/content/posts/images/`，正文用路径引用：

```md
![图片说明](./images/photo.jpg)
```

实际图片文件名和扩展名必须与链接一致。

### 本地检查文章再发布

1. 保存文章（`Ctrl+S`）。
2. 确认 `draft: false`。
3. 运行 `pnpm dev`，在浏览器打开本地网址，查看首页和文章内容。
4. 满意后按“第 8 节”提交推送。新文章会在部署成功后出现在网站上。


## 5. 管理公告和“了解更多”

公告由 `src/config/announcementConfig.ts` 控制。当前公告正文为空，“了解更多”按钮保留但关闭了链接。

- 编辑 `content: "这里写公告"` 可以添加公告内容。
- 想让“了解更多”跳转时，把 `link.enable` 改为 `true`，填写 `text` 和 `url`。
- 不想显示公告卡片时，在 `src/config/sidebarConfig.ts` 把公告模块的 `enable` 改为 `false`（左侧和移动端配置分别控制）。

## 6. 更换音乐或封面

把音频文件放进 `public/assets/music/`，把封面图片放进 `public/assets/music/cover/`。然后在 `src/config/musicConfig.ts` 的 `local.playlist` 中修改歌曲名、歌手和路径。例如：

```ts
name: "主角",
artist: "马里奥",
url: "/assets/music/你的音频文件名.mp3",
cover: "/assets/music/cover/你的封面文件名.png",
```

路径必须和文件名完全一致。文件名尽量避免空格；中文文件名也可以使用。音乐和图片属于仓库文件，提交时需要一并加入。

## 7. 上传自己的旅行相册

相册照片放在 `public/gallery/`，相册资料写在 `src/config/galleryConfig.ts`。你当前的相册页面开关是关闭的，而且配置中还有 Firefly 模板示例；添加自己的相册时按下面步骤操作：

1. 在 `public/gallery/` 下新建一个英文或拼音文件夹，例如 `my-trip-2026`。
2. 把这次旅行的照片复制到该文件夹。建议先挑选清晰、横竖比例合适的照片，并缩小过大的原图以控制网页加载速度。
3. 如需指定封面，把一张图片命名为 `cover.jpg`（也支持 png、webp、avif 等）。不设置封面时会用相册里的第一张照片。
4. 打开 `src/config/galleryConfig.ts`，在 `albums` 数组里新增一个对象；`id` 必须与文件夹名一致。例如：

   ```ts
   {
     id: "my-trip-2026",
     name: "云南旅行",
     description: "和朋友一起记录旅途中的风景。",
     location: "云南",
     date: "2026-10-01",
     tags: ["旅行", "云南"],
   },
   ```

5. 删除或改写 `galleryConfig.ts` 中原来的 `firefly-2026` 和 `encrypted-test` 示例对象，避免发布别人的示例照片。
6. 打开 `src/config/siteConfig.ts`，把 `gallery: false` 改成 `gallery: true`，相册页面和导航入口才会开放。
7. 运行 `pnpm dev` 本地预览。确认相册、封面和照片正常后，再提交并推送。

如果想保留原照片但暂时不显示，保持 `gallery: false`；如果将来想重新开放，记得先清理模板示例相册。

## 8. 本地修改后发布到线上

先在本地预览确认，再提交并推送。每次发布都在**内层项目目录**运行：

```powershell
cd D:\code-MS\blog\Firefly
git status
git add .
git commit -m "feat: update blog content"
git push origin master
```

简单解释：

1. `git status` 查看哪些文件改了。
2. `git add .` 把当前项目里的改动放进本次提交。
3. `git commit` 给这次改动保存一个记录。
4. `git push origin master` 把提交上传到 GitHub。

`git add .` 会包含该项目里所有新增和修改文件。若看到不认识的文件，先停下来，把 `git status` 结果发给熟悉 Git 的人确认。不要在外层目录运行这组命令。

## 9. 检查部署是否成功

这个仓库的 `.github/workflows/deploy.yml` 配置为：每次推送到 GitHub 的 `master` 分支后，GitHub Actions 自动构建并部署到 **GitHub Pages**。

上传后打开 GitHub 仓库的 **Actions** 页面：

- 绿色勾号：构建和部署成功。
- 红色叉号：部署失败；点进去查看失败步骤和错误信息。
- 正在转圈：还在构建，等它结束再查看网站。

成功后打开 `https://blog.xusun.eu.cc/`。如果 GitHub Actions 成功但域名内容没更新，先用浏览器无痕窗口检查，再确认 Cloudflare DNS/自定义域名仍指向这个 GitHub Pages 站点。Cloudflare 托管 DNS 本身不会自动把仓库部署到 Cloudflare Pages；实际部署目标以 Actions 工作流显示为准。

## 10. 常见问题

- **`Recv failure: Connection was reset`：**通常是网络连接 GitHub 时被中断。先确认提交已创建（`git log -1 --oneline`），换网络后重试 `git push origin master`。
- **提示 CRLF 会转成 LF：**这是 Windows 和 Linux 换行格式提醒，一般不是错误，可以继续。
- **网站还是旧内容：**先看 GitHub Actions 是否绿勾；再确认 VS Code 打开的是 `D:\code-MS\blog\Firefly`，不是外层目录。
- **想撤销本地未提交修改：**先不要运行 `git restore` 或 `git reset`。它们可能丢弃内容；先复制文件或询问再处理。

## 11. 每次发布记住这四步

**改文件 → 本地预览 → GitHub Actions 看部署 → 浏览器打开线上网址。**
